# 首次接手 · 初始化清单

**先跑这一条，它会告诉你还缺什么：**

```bash
python tools/bootstrap.py --all      # 看不动手：--check；只补子模块不加参数即可
```

> 本分享仓**已随附上游副本与模拟器构建产物**（`dist/`、`presets/`），所以不需要 clone 上游、
> 也不需要 `pnpm build`。真正需要在你机器上做的只有下面几项。
> 命令里的 `<工作区根>` 替换为你本机这个目录的绝对路径（例如 `D:/work/miliastra`）。

---

## 0. 为什么必须做（失败是静默的）

| 漏掉 | 症状（都不报错，只是不生效） |
|---|---|
| 技能未注册 | AI 看不到 4 个技能，只能靠猜文档 |
| MCP 未接入 | AI 无法操作模拟器（编辑工程 / 试玩 / 截图全无） |
| 子模块未初始化 | 4 个目录为空（知识库语料、节点图工具子服务缺失） |
| 依赖未安装 | 模拟器/MCP 起不来（`node_modules` 未装） |
| 奇匠等级 < Lv.2 | 真机文字不渲染，底框正常，像代码 bug |

## 1. 上游副本与构建产物（**已随附，无需 clone / 无需 build**）

MiliastraAgent、miliastra-beyond-simulator 与 `refs/` 下 12 个参考仓库，以及上游 `.gitignore`
排除的构建产物（`dsh-plugin/dist`、`mcp/dist`、`web/dist`、`dsh-plugin/presets`）**都已随仓提供**
—— 用 `git clone --recurse-submodules` 拿到即可用。

需要你补的只有两项：

```bash
# ① 4 个子模块（漏了 --recurse-submodules 时补拉；含知识库语料）
#    ⚠️ 国内网络：这 4 个子模块的上游都在 github.com，直连不通，需先设代理，例如
#       Windows:  set HTTPS_PROXY=http://127.0.0.1:7897
#       Linux/macOS:  export HTTPS_PROXY=http://127.0.0.1:7897
git submodule update --init --recursive

# ② 模拟器的运行期依赖（node_modules 平台相关，无法随仓分发）
cd <工作区根>/miliastra-beyond-simulator
pnpm install --frozen-lockfile
```

> 需要 Node.js 22+ 与 pnpm（`npm i -g pnpm`）。
> 两条都可交给 `python tools/bootstrap.py --install` 自动完成。
> 校验：`miliastra-beyond-simulator/mcp/dist/index.js` 存在即 OK。

> ⚠️ 本仓不含上游 `.git`，因此 `git pull`、`py tools/check_upstream.py --fetch` 不可用；
> 要更新上游内容请回各自仓库（见 `refs/README.md` 台账）。

## 2. 注册技能（4 个）

把三个技能目录登记进 Hermes 的 `skills.external_dirs`（**必须换成你自己的绝对路径**）：

```bash
hermes config set skills.external_dirs '["<工作区根>/refs/Miliastra-toolbox/skills","<工作区根>/miliastra-beyond-simulator/agent/wonderland-lua-builder/skills","<工作区根>/tools/hermes-skills"]'
```

应得到 4 个技能：

| 技能名 | 内容 |
|---|---|
| `qxqy-game-studio` | 七步制作流程（+ `references/` 八份） |
| `miliastra-knowledge` | 官方文档检索（服务端节点 / 指南 / 教程 / FAQ） |
| `miliastra-knowledge-lua` | 客户端控件与 Lua 文档 |
| `qxqy-simulator` | Hermes 侧模拟器适配层（本工作区自建） |

> ⚠️ 知识库查询会发往第三方服务 `https://ugc.070077.xyz`（**数据出网**，许可为 Proprietary，仅本机自用）。

## 3. 接入模拟器 MCP

```bash
hermes mcp add qxqy-simulator --command node --connect-timeout 120 \
  --args "<工作区根>/miliastra-beyond-simulator/mcp/dist/index.js" \
         --workspace "<工作区根>/projects" --web-url http://127.0.0.1:4173
hermes mcp test qxqy-simulator
```

- 期望：**Connected + 11 个工具**（`qxqy_project_open`、`qxqy_studio_get/patch/play`、两张截图、`preview_*`、`script_sync`）。
- 工具在会话里以 `mcp_qxqy_simulator_*` 为前缀。
- **改配置后需重启宿主或执行 `/reload-mcp` 才生效**（无热加载）。
- `--workspace` 必须与 Web 预览指向同一目录，否则预览桥接会明确拒绝。

## 4. 自检（确认前面几步真的生效）

```bash
cd <工作区根>
python tools/bootstrap.py --check    # 一键：缺什么、下一步敲什么（不做改动）
py tools/audit_workspace.py          # 总检，退出码 0 = 无告警
py tools/check_skill_registry.py     # 技能是否全部注册
py tools/check_integration.py        # MCP / refs 登记 / 台账接入列
```

三者都应 **exit 0**。若 `check_skill_registry` 报"未注册技能"，回到第 2 步；
若 `check_integration` 报"台账称已接入 MCP 但无 `mcp_servers`"，回到第 3 步。

## 5. 真机侧（只有要上真机时才需要）

| 项 | 说明 |
|---|---|
| **账号奇匠等级 ≥ Lv.2** | 未达标时真机**文字不渲染且不报错**（底框正常）；模拟器看不出问题。查法见《工具书》顶部「等级门槛 · 唯一权威说明」 |
| **部署路径** | 编辑器只认 `…/LocalLow/miHoYo/原神/BeyondLocal/<UID>/Beyond_Local_Save_Level/<编辑器ID>/external_lua_file/…`；母本改完必须同步，用 `python tools/deploy_lua.py <脚本>`（复跑门禁 → 自动发现映射目录 → 同步 → sha256 回读） |
| **索引回收** | 导入 `.gia` 后用户仅需 Ctrl+S，随后 `python tools/gil_id_extract.py --latest --json out.json` 直读「模板名→真机ID」；**索引不可推算，只能逐条直读** |
| **本地编辑器操作** | 导入资产、建容器、挂载脚本、保存关卡——**均需人工**，操作卡见 `tools/导入操作卡模板.md` |
