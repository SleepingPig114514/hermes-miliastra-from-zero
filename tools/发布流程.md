# 发布流程 · 源工作区 → GitHub

> **定位**：本工作区（`千星沙箱/`）是**唯一真源**；对外分享的那份是它的**派生品**，
> 由 `tools/make_share.py` 一条命令生成，不手工维护、可随时删掉重生。

---

## 一条命令

```bash
cd <工作区根>
python tools/make_share.py --remote https://github.com/<你>/<仓库>.git
```

它依次做 7 步（`--check` 可先只看要做什么）：

| # | 步骤 | 关键点 |
|---|---|---|
| 1 | 复制源工作区 | 排除 `projects/`、`.git/`、`node_modules/`、`__pycache__/`、Godot `.import/`、RAG 向量库 |
| 2 | 套用发布版覆盖文件 | `tools/share/overrides/**` 按目录结构覆盖到输出物 |
| 3 | 补回上游跟踪文件 | 按各上游仓库的 `git ls-files` 强制 `add -f` |
| 4 | 纳入构建产物 | `dist/`、`presets/`、`web/public/*` → clone 后无需 `pnpm build` |
| 5 | 注册 4 个 submodule | SHA/URL 从源工作区的上游仓库**动态读取**，跟随上游更新 |
| 6 | 泄漏自检 | 扫真实账号 UID 与本机用户名路径（有命中则**拒绝推送**） |
| 7 | git init + commit + 推送 | 远端已有历史时做**增量提交** |

常用参数：

```bash
--check           # 只报告，不写盘
--out <目录>      # 指定输出目录（默认 <工作区根>-share）
--force           # 输出目录非空时先清空
--remote <URL>    # 配 origin 并推送
--push            # 推送到已配置的 origin
```

## 为什么要有 overrides（两版语境分离）

同一份文档在「作业台」与「发布物」里的说法**正好相反**：

| 文件 | 源工作区（作业台） | 发布物 |
|---|---|---|
| `README.md` | 不含上游副本，需自行 clone | 上游已剥离 `.git`，随附 |
| `tools/首次接手.md` | 先 clone 上游再 build | 已随附，只需子模块 + 依赖 |

→ 发布版放在 `tools/share/overrides/<同路径>`，生成时覆盖过去；源工作区保持作业台语义。
**改这两份文档时两边都要改。**

## 三条硬规则（都是真踩过的坑）

1. **绝不 `git add -A`**（推送阶段）
   输出目录里 4 个子模块目录是**空的**，`git add -A` 会把它们的 gitlink 索引项清掉
   → clone 下来 4 个子模块全空。脚本用 `reset --soft` + 直接提交索引来规避。

2. **上游 `.gitattributes` 必须补 `* -text`**
   Git 规则「目录越深优先级越高」，根目录的 `.gitattributes` **盖不过**上游自带的。
   不补的话 `git add` 会把源工作区的 CRLF 规范化成 LF（实测 3653 个文件与源不一致）。
   目前已补：`refs/Ayaya_Miliastra_Editor/`、`refs/ikemen/`。
   **新增上游仓库时若它自带 `.gitattributes`，要一并检查。**

3. **比对差异必须解析 `ls-tree` 的三段**（`mode type sha`）
   写成 `mode, sha, _ = meta.split()` 会把 `blob`/`commit` 当成 SHA，
   导致"差异 0"的**假结论**（实测因此漏掉 3660 个文件的换行符变化）。
