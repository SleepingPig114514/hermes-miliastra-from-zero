# GIL-ID 回收 runbook — 从真机存档直读「模板名 → 重映射ID」

> 登记：2026-10-10（工具书八·11 销账产物）。P0 证据：battle-city 真机存档实测（首轮 `1073741826.gil` 41 条；**`1073741828.gil` 47 个 BC_ 模板全解出**，抽查 `BC_tank_player_a`=1073741845 与检视器一致）。
> ⚠️ **2026-10-10 更正**：早期"同包连号"结论**已被证伪**——47 模板实测 ID 不连号（见 §五）。

## 一、什么情况下使用

任何项目走 `.gia` 资产通道（流程规范 v2 的 P2/P4 阶段），**导入编辑器之后**需要"模板名→真机控件模板索引"映射时，一律用本方法回收，**不再让用户逐个复制索引**。典型触发句：

- 用户说"导入好了"→ 下一步就是跑本脚本，而不是向用户索取索引清单；
- 迭代轮重导资产（重名 `_1` 语义）后需要刷新 annotations.lua；
- 校验用户手抄的索引是否抄对（交叉核对）。

不适用：图片资源 ID（SetImage 的 imageId）与音效 ID——那些是编辑器内配置项，不在关卡 .gil 的模板段，仍按旧口径向用户索取【待复核：音效/图片 ID 是否也在 .gil 其他段，未查】。

## 二、原理（为什么能拿到）

`.gia` 导入会把模板索引重映射（索引不可预测定律，P0）。但关卡存档 `.gil` 内，每个控件单元（GraphUnit）的 field 501 同时携带两份数据：

| tag | 含义 |
|---|---|
| `a8 1f` + varint | 该单元**重映射后的 ID**（1073741xxx 族） |
| `aa 1f` + string | 该单元**名字**（UTF-8，随 .gia 原样保留，不受重映射影响） |

ID 在名字前 **≤2048 字节**内，按"最近前邻"配对即可（窗口值来历与坑见五节）。名字是唯一主键——这就是**包内命名纪律**存在的原因。

## 三、怎么使用

```bash
# 在 千星沙箱/ 下执行；Python 3.9+，零第三方依赖
python tools/gil_id_extract.py "<存档.gil路径>"
python tools/gil_id_extract.py --latest                 # 自动取所有 UID 下最新修改的 .gil
python tools/gil_id_extract.py --latest --uid <你的UID>   # 限定用户 UID
# 出机器可读产物（回填 annotations.lua 用）
python tools/gil_id_extract.py --latest --json out/gil_ids.json --tsv out/gil_ids.tsv
```

存档路径规律：`%USERPROFILE%\AppData\LocalLow\miHoYo\原神\BeyondLocal\<UID>\Beyond_Local_Save_Level\<地图ID>\<地图ID>.gil`（`Temp\` 下有镜像副本，读正式目录那份）。

**两层编号都要先确认（2026-10-10 加，工具已内置输出）**：UID 与地图ID 都可能认错，工具现在**一律打印身份**——

```
[自动发现] UID=<你的UID>  地图ID=1073741829  563400 B  保存=2026-10-10 16:49
[其他候选 1 个] 1073741830（2026-10-10 16:03，24802B）
⚠ AI 必须把【UID + 地图ID】报给用户确认；不对就显式传 .gil 路径或 --uid。
```

- **UID 用户能自己看**：游戏内试玩画面右下角水印 `UID: …`，或「个人信息」页 → 报给用户即可秒确认；
- **地图ID 用户看不到**（编辑器不显示这个数字，它就是文件夹名）→ **AI 列候选 + 指纹让用户认"是我刚存的那张"**，禁止反问用户地图ID是多少。

**输出判读（重要，原始输出含噪声）**：
1. 输出分三段：①模板定义段（先出现，权威）②平台自带 UI 元素（默认布局/小地图/摇杆…1825–1844 族，忽略）③场景实例段（同名再出现，是"模板引用控件"实例，其 ID 是实例 ID 不是模板索引，忽略）——**取每个名字的首次出现**；
2. 与导入清单核对：包内 N 个模板应解出 N 条。⚠️ **不要拿"连号"当判据**（2026-10-10 更正：模板 ID 不连号）。条数不足 / 名字缺失 = 导入未落地或有重名，停下人工查；
3. 回填：把 `名字→ID` 写进项目 `annotations.lua`，脚本头部保留 `TPL_X = TPL_X or <真实值>` 注入通道。

## 四、需要用户配合什么（全部动作）

| 步骤 | 用户动作 | 说明 |
|---|---|---|
| 1 | 把 AI 给的 `.gia` 放 `Beyond_Local_Export\` 根目录 → 资产导入导出管理 → 加载外部资产 → 转移 | 既有 P0 通道，不变 |
| 2 | 编辑器内 **Ctrl+S 保存关卡**（把模板拖进场景与否都行，保存即落 .gil） | 唯一新增动作，替代逐个复制索引 |
| 3 | **核对 AI 报出的 UID / 地图ID**（AI 用 `--latest` / `--list` 自动发现并列候选+指纹） | ⚠️ 用户界面**看不到地图ID**，不能反问"你的地图ID是多少"；多账号/多存档时 AI 必须报出【UID+地图ID+保存时间+大小】让用户认"是我刚存的那张" |
| 4（仅每项目首轮） | 抽查 1 条：编辑器里点该模板 → 检视器索引 == 脚本解出的 ID | 校准【待复核】假设"存档 ID=检视器 prefabIndex"；对一次即永久销账 |

## 五、边界与坑

- **prefabIndex 不落关卡 .gil 的旧疑问已反转**：2026-10-10 实测它就在（a8 1f varint）；此前"1846/1850 不在 .gil"是找错了对象（那是旧手工模板，且当时在找 fixed32/ASCII 编码，实际是 varint）。
- 名字含不可打印字符/超长（>64B）的单元会被跳过（脚本防误报）。
- ⚠️ **配对窗口必须够大（2026-10-11 修正：400 → 2048 字节）**：ID 距名字的字节数随**该模板子图元数量**增长——实测 128 子项的模板 **687 字节**、65 子项的 372 字节。旧值 400 会把 128 子项的大模板**整批漏掉**，而且漏得"看起来正常"：子图元名照常配对、只有模板名消失（实测 art-lab 28 个模板漏 6 个：报告 877 条 vs 应得 883 条）。现值为 **2048**（3 倍余量）；配对规则仍是"取最近的 ID 区前邻"，窗口放大不会改变就近结果（同一单元内本单元的 ID 必然最近）。
- ⚠️ **一个 ID 只归最近单元（去重规则，2026-10-11 加）**：窗口放大后，**没有自己 ID 字段的场景对象**（出生点 / 预设点之类）会蹭到前一个单元的 ID（实测 `出生点1`、`新建预设点` 双双配到 `容器节点` 的 1073742707）。脚本现按"同 ID 只保留距离最小者"去重——本单元的 ID 必然最近，故该规则等价于"谁的 ID 谁拿走"。回归三态：旧窗口 877 / 放大未去重 885（+8，含 2 条假配对）/ **放大+去重 883 = 877 + 补回的 6 条**，零丢失、零重复。
- **判据**：回收条数必须与**导入清单**逐条核对（数量相等 + 名字齐全），**再叠一层独立复算**（照 §三.1 的字段规则自写一遍解析器做集合比对）。别把"跑了一遍工具"当验证——本次 6 条漏配就是靠"名字清单对不上"抓到的，只跑工具永远发现不了。
- 若某轮 .gil 更新导致字段号 501 不再是 a8/aa 1f（版更风险），脚本会输出 0 配对、退出码 2——**此时不许猜，回报用户转人工复制索引**，并更新本 runbook。
- ⚠️ **"同包连号"已证伪**（2026-10-10，battle-city 47 模板实测）：ID 不连号，间隔随每个模板的**子图元数量**变化（坦克族 +18、砖 +5、道具 +4~20）。早前 1881–1885 那组只是子模板数恰好一致的巧合。**一律以脚本逐条直读为准，禁止任何推算**；改了资产必须整表重收。
- `.gir` 运行时快照（`Beyond_Local_Save_Runtime\`）含十进制 ASCII ID 文本与 `go<ID>` 实例名，是旁证源，不是主通道（无名字配对结构）。
- ⚠️ **多 UID / 多存档误选（2026-10-10 实测）**：`BeyondLocal\` 下会有**多个 UID 目录**（本机实测 16 个，其中 15 个是游戏缓存的其他玩家空壳目录）；同一 UID 下也会并存多张图。`--latest` 只按 .gil 保存时间取最新，**空图目录的 mtime 可能更晚 ⇒ 会选错**（会把脚本/索引对到错的那张）。现已改为两个工具**一律打印身份 + 列出其他候选**（见三节）；**AI 必须把 UID 与地图ID 报给用户确认**。显式指定：deploy 用 `--uid` / `--map-dir`，extract 直接传 `.gil` 路径。**只靠自动发现、不向用户报出身份 = 违规**。

## 七、端到端闭环（资产路线全流程，六步）

> 定位：从"AI 写完代码"到"用户真机看到效果"的完整链路。每步写清：谁做、命令、产物、失败分支。
> 原则：**模拟器只做效果验证，它的 ID 是假的、不进交付物**；真机 ID 只在导入后从存档回收一次，之后全自动。

| 步 | 执行人 | 动作与命令 | 产物 | 失败分支 |
|---|---|---|---|---|
| **0 AI 前置**（2026-10-11 加） | AI | ① `.gia` 复制到 `Beyond_Local_Export\` **根**，并**把该目录里的旧版包移入回收站**（编辑器会把目录下所有包一起列出，用户会选错版本）；② 录一份**存档基线指纹**（各 `.gil` 的 路径/mtime/size/sha16 + 有无脚本），存项目 `lua_out/baseline_gil.json`；③ 用户新建图/换图后，**diff 基线找出新出现的 `.gil`**（或直接用 `deploy_lua.py --list` 的「← 最近保存」标记）→ 报给用户确认 | 投递好的包 + 基线指纹 + 确认后的目标地图 | 目录里有重名/`_1` 包→先清走再让用户导入；新图认不出→列候选表让用户认（**不要反问"地图ID是多少"**，界面不显示） |
| **1 双轨验证**（导入前，可反复） | AI | ① 逻辑门禁：`node MiliastraAgent/release/tools/sandbox/run_headless.mjs <脚本> --fuzz 3000 --json`（errors/unsupported/neverActivated 归零）；**② 脚本兜底表是真机索引时**：门禁必须带 `--annotations <项目>/lua_out/annotations_sandbox.lua`，否则会因"真机有、沙箱未实现"的字段（`showCursor`/`adaptiveFontSize`）假失败；③ 视觉基线：beyond 渲染截图——**给用户看的"效果"只能出自这里** | 沙箱报告 JSON + 基线 PNG | 任一项不过→改代码重跑，**不出包**（不消耗用户导入机会） |
| **2 出包** | AI | beyond studio 把美术烘进 `save.json`（唯一事实源）→ 导出 `.gia`；命名 `项目前缀_用途_vN`（名字=主键，包内唯一）；导出前过 `validateGiaCompatibility`；**自留导入清单**（名字→包内顺序→预期用途，存项目目录） | `.gia` + 导入清单 | loss 警告逐条处置后才交用户 |
| **3 导入+保存**（用户唯一动作轮次） | 用户 | 按《导入操作卡》（模板见 `tools/导入操作卡模板.md`，**出卡前过一遍模板里的「出卡自检」三条**）：`.gia` 放 `Beyond_Local_Export\` 根 → 资产导入导出管理 → 加载外部资产 → 转移选中 → **Ctrl+S 保存关卡**（落 .gil）→ 回报"完成+地图名"。⚠️ **全程在编辑器内**（游戏试玩界面没有这些菜单） | 磁盘上的新 `.gil` | 找不到入口→以用户截图为准调整操作卡；转移报错→对照 `probes/client-template-import/` 样本拆包排查 |
| **4 ID 回收** | AI | `python tools/gil_id_extract.py --latest --json out/gil_ids.json`；批量取用：`py tools/gil_id_extract.py "<地图目录>\<地图ID>.gil"`（**参数要原生路径**，MSYS 的 `/c/...` 会报"文件不存在"）；与步 2 导入清单逐条核对。**容器节点/客户端控件容器也在 `.gil` 里按名出现，一并解出**（2026-10-11 实证），**不需要让用户复制容器节点索引** | 名字→真机ID 表 + 容器节点索引 | **断号/缺名→停下人工查，禁止推导补齐**；脚本退出码 2→字段号变更，转人工复制索引并更新本 runbook |
| **5 回填+部署** | AI | ① ID 表写进项目 `annotations.lua`；② 替换 `levelScript.lua` 头部 `PS_X = PS_X or <真值>` 兜底；③ `python tools/deploy_lua.py <脚本> --annotations <项目>/lua_out/annotations_sandbox.lua --map-dir "<地图目录>"`（内部复跑门禁→同步到 `external_lua_file\`→回读 sha256 一致才报成功）。`--map-dir` 给**含 `<地图ID>.gil` 的那一级**（层级不对立刻退 3 并提示） | 部署完成的真机脚本 | 复跑门禁 fail→不部署（先确认是不是"沙箱未实现字段"，是就给 `--annotations`）；sha256 不一致→报错停手（防 1825→1826 换号类事故） |
| **6 真机验收** | 用户 | 进编辑器试玩。**画面正常出现即已间接销账「存档直读 ID ＝ `InstantiateClientUIControl` 可用模板索引」**（直读 ID 建不出模板就不会有画面）；仍可顺手做一次直接抽查：点 1 个模板→检视器索引==步 4 解出值 | 验收结论；`runtime_verified` 才允许翻绿 | 视觉与基线不符→登记四项未仿真差异之一→回步 1；索引对不上→ID 语义假设崩塌，全链路转人工并回滚 annotations |

**迭代轮简化**：只改逻辑→步 5③ 一条命令（deploy_lua.py 已含门禁）；改了资产→步 2–5 重走（重名 `_1` 语义：新名导入+删旧+重收 ID 三步一体），用户动作仍是"导入+Ctrl+S"。
**画面异常先 Ctrl+S 再试玩**：存档里内嵌的是脚本副本，部署只改了磁盘文件；不生效就在编辑器重存一次刷新内嵌副本（2026-10-11 实测口径）。
