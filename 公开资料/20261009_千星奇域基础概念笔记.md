## 一、平台是什么

- 【官方】**千星奇域（Miliastra Wonderland）**：《原神》2025 年 10 月（月之二/6.1 版本）上线的官方 UGC 模块。玩家创作身份称「奇匠」，用编辑器「千星沙箱」调用原神本体的玩法系统与美术资产（模型、动作、特效、怪物、音效、战斗/元素反应/物理），制作关卡并发布给其他玩家游玩。
- 【官方】立项背景：2022 年须弥上线后团队意识到官方产能有瓶颈；愿景是"到 2030 年为 10 亿人打造虚拟世界"；研发历时两年（一年概念设计+一年技术落地），基于 Unity 引擎与原神架构定制。
- 【第三方】**编辑器仅限 PC 端**（Win10/11 64-bit，第十代 i5 / Ryzen 同级起）。解锁门槛：冒险等阶 ≥28 + 完成魔神任务序章第三幕"捕风的异乡人"。
- 【官方】**奇匠学院**（act.mihoyo.com/ys/ugc/tutorial，需创作者权限）：阶梯式系统教程；另有奇匠论坛（米游社）、B 站官方《千星奇域实操创作教程》16 P、千星奇域资源中心（关卡文件与素材文件共享）。
- 【官方】内容分两种模式：**超限模式**（自定义角色、全新多人玩法规则，适配竞技/合作）与**经典模式**（月之四版本 2026-01-14 加入，玩家可邀请提瓦特经典角色进入奇域游玩）。新功能不限于超限模式，技术可行即两边都落地。
- 【官方】生态数据（2026-01 首届创作者交流会）：3 万+ 全球创作者、累计游玩 1.5 亿人次、部分关卡海外收入超境内；2026 三大方向：开放度、收益、生态——持续升级编辑器、提升商业化激励、升级宣发流量；未来将支持**素材导入**与**元件开源**。
- 【官方】收益体系：创作激励计划 + 关卡礼盒（免费发放或售卖，销售收入转化为创作者激励）。

## 二、核心对象模型（ECS 风格）【官方演讲与第三方评测口径一致】

| 概念 | 含义 |
|---|---|
| **元件** | 预设的实体数据=创建实体的模板（含实体类型、模型/特效/音效、战斗属性、挂载的组件与节点图）；可保存复用、导入导出 |
| **实体** | 元件在关卡中的具象化实例，承载功能的最小集合；玩家、敌人、宝箱、机关、触发器皆为实体 |
| **可编辑实体** | 编辑器摆放产生，有全局唯一 GUID；数据引用元件，实体上的单独修改=覆写引用，未覆写部分随元件更新推送 |
| **临时实体** | 运行时节点图【创建元件】动态生成，无 GUID；仅动态物件元件和造物元件可动态创建，静态元件不可 |
| **组件** | 挂给实体的功能模块，引擎层实现（性能优于节点图）；**只能编辑时增删，运行时仅可启停** |
| **属性** | 实体/组件上的可调参数，由节点图或事件修改 |

底层框架四要素（GDC 官方口径）：预制体（Prefabs）、实体（Entities）、属性（Attributes）、组件（Components）。

**单位六大类型**【第三方整理，术语与官方一致】：
1. **关卡实体**：每关有且仅有一个，场景"总控制器"；关卡开始自动创建、结束销毁；只有位置无旋转缩放；挂全局逻辑（计时/计分/胜负）、全局变量、收发信号。
2. **玩家实体**：纯逻辑抽象实体，描述"角色的从属概念"，无物理实体。
3. **角色实体**：玩家实际操控的单位；属性由职业决定（技能、战斗属性）；超限模式下每玩家对应一个角色。
4. **造物**：人型生物/元素生物/深渊魔物/魔兽/小动物/机械等具战斗属性实体；有生命/攻击/防御，可加 Buff/Debuff；AI 行为按编辑时配置（未入战：闲逛/站立；入战：主动攻击/被动反击/逃跑/巡逻），运行时不可动态替换行为模式；可配仇恨系统与掉落。
5. **物件**：地貌、植被、建筑、装饰、机关统称。动态物件可挂组件+节点图、可配预设状态动画；静态物件纯表现装饰，不支持任何功能组件。
6. **本地投射物**：本地计算与呈现的投射物实体；需编辑时预定义才能被技能节点图引用；靠投射运动器决定轨迹、命中检测决定判定。

实体的通用变换：位置（X/Y/Z）、旋转（多数仅绕 Y 轴 0–360°）、缩放、朝向向量。生命周期事件：创建时/初始化完成时/销毁时，均可在节点图监听。

## 三、逻辑系统：节点图（主干）+ 客户端 Lua（旁路）

- 【官方】**节点图是首选逻辑工具**：官方明确"脚本语言上限更高但学习难度大，因此优先可视化节点而非代码"。类比 Unreal 蓝图，"如果/则"连线。
- 【第三方】连线两类：**执行流**（定顺序）与**运算流**（传数据，按需反向溯源求值，不接执行流则永不计算）。**强类型**（9 种基础类型：实体、GUID、整数、浮点数、布尔、字符串[限约40英文字符]、三维向量、元件ID、配置ID；均有对应列表类型），仅同类型引脚可连；禁止环形连线；节点执行失败返回默认值不中断流程。
- 【第三方】节点五大类：事件（起点，只出不进）、执行（做事）、流程控制（双分支/多分支/循环/跳出）、运算（数学/逻辑/类型转换）、查询（获取实体/组件/配置信息）。可封装**复合节点**（≈自定义函数，可导出分享）。
- 【第三方】6 种节点图类型，分服务器/客户端两侧——这是关键架构：
  - 服务器（权威判定）：实体节点图（生命周期随实体）、单位状态节点图（Buff/Debuff 载体）、职业节点图、道具节点图；
  - 客户端（本地表现）：技能节点图（挂技能时间轴，**只能做特效/音效/镜头/UI，不能做伤害与状态逻辑**）、本地过滤器节点图（布尔/整数，用于命中筛选等返回判断）。
  - 官方演讲解释：为保证跨平台数据留存与联机有效性，大部分玩法数据采用**服务端权威判定**，仅角色技能等核心表现由客户端主导。
- 【官方】时空模型（Space-Time Model）：时间函数+物体运动函数+角色位移函数；运动序列逻辑重设计，物体运动按特定时间点直接计算，不靠服务器逐帧算轨迹（部分投射物/实体运动与该系统不完全兼容，属官方承认的取舍）。
- 【第三方】跨实体通信：**服务器信号**——信号管理器自定义信号名+带类型参数，节点图发送/接收（如"据点受伤"信号发给关卡实体）。
- 【第三方】技能系统结构：技能配置（类型：瞬发/长按/普通/连段/瞄准；冷却/次数/消耗/索敌/空中释放等）+ **时间轴**（关键帧）+ **能力单元**（8 种预定义效果纯数据：攻击盒攻击、直接攻击、播放特效、创建本地投射物、添加单位状态、移除单位状态、销毁自身、恢复生命），能力单元须被节点图/命中检测/本地投射物调用才生效。
- 【官方+项目侧】**界面控件 + 客户端 Lua 脚本**：后加的 UI 层通道，用于 2D 玩法与界面动效。与节点图两条路线并存非替代。注意：该 Lua 只挂在 2D UI 控件树上，无相机/场景/物理接口（详见项目 `release/Lua客户端控件API文档.md` 与另轮分析结论）。

## 四、关卡与场景制作基础

- 【第三方】**关卡设置**（局内编辑器→系统菜单→关卡设置）八项：基础预设（场景范围/人数限制）、阵营设置（玩家/物件/敌人的团队标签与友善/敌对关系，驱动默认攻击逻辑与条件判断）、出生点、复苏点（死亡重生点）、人数与分组设置、加载界面配置、结算逻辑、地形导航（怪物寻路网格）。
- 【第三方】地形：方块化（体素式）编辑；最小单位单层地块 5m×5m、层高 2.5m；笔刷：创建/删除/抹平（1–10 层）、斜坡（正向/左/右，材质随地块）、水体、路径；相连地块合并为一块地形；【待复核】材质仅 7 种（草地/石头/木板/冰面/岩浆/沙地/金属），不能做曲面、不能自定义材质——基于 2025-10 超测版，后续版本可能已扩充。
- 【官方+第三方】资产政策：模型/特效/音效只能用官方库，**不能导入自定义模型**（官方规划未来开放素材导入）；配置类资产（元件、节点图、复合节点）可导出 .gia / 资产包 .gpk 在创作者间分享，导入时自动检测依赖。
- 【官方】已封装的系统组件（降门槛的抓手）：仇恨阵营、掉落道具、护盾机制、天赋系统、装备道具、自定义载具、造物系统（月之四起可自定义怪物种类与攻击机制）等。

## 五、性能与限制

- 【第三方】关卡数量限制维度（具体数值【待复核】，以编辑器负载检测工具实测为准）：地块数/地形高度上限；预放置实体数、运行时实体总数（超测口径约 1000）、单实体组件数；单节点图节点数、嵌套深度、关卡节点图总数；公测联机人数口径 8 人。
- 【第三方】官方优化建议：能用组件就不用节点图（引擎层更快）；避免"每帧触发"跑复杂逻辑，改用定时器；缓存查询结果；远处实体走视野检测卸载（LOD）；控制同屏特效数；UI 只在数值变化时更新、列表用对象池。
- 【官方】"一关一存"历史问题：早期编辑数据与运行数据共用一份存档，导致参数冲突与体积问题；后改为**编辑数据与游戏运行数据彻底分离**，编辑端参数不再影响玩家下载量。

## 六、对千星沙箱 2D 项目（MiliastraAgent）的意义

平台主干=服务端权威 + 节点图 + 原神现成组件的 3D 体系；客户端 Lua + 界面控件是叠在其上的纯 UI 层旁路。项目手册"2D 玩法不依赖现成组件、一切从零实现"即放弃主干、只走旁路：重力、碰撞、输入、渲染表现全要在 Lua 控件树里自造——这就是 qx2d 工具与体外沙箱存在的原因。
